# Core observability cost instrument

| Pair | Identical work within pair | Deliberate difference |
|---|---|---|
| CorePassTimingOff / On | 65,536 callbacks, one callback per core pass; same actor type and checksum | `setPassTiming(false/true)` before startup; expected completed-span count 0 / 65,535 in the final snapshot |
| CoreStatsUnrequested / Requested | 65,536 callbacks; same sum of loop indices | Obtain the index from `LoopEvent` / `getCoreStats()`, escaping the full snapshot; additional per-pass snapshot requests 0 / 65,536 |
| CoreDeadLetterUnset / Counting | 65,536 unhandled same-core events to a live actor, then one FIFO Done | Empty handler / handler that increments a plain worker-owned count; callbacks 0 / 65,536 |

All pairs use one core, explicit `NoAffinity`, zero latency, `start(true)` and `join()`. They do not change the caller's affinity. The duration is **microseconds per whole batch**, including worker startup, the actor's `onInit`, runtime teardown/join and one final owner-thread snapshot. Engine construction, factory registration, engine destruction and verdicts are paused. `SetItemsProcessed` and rate counters use 65,536 callback passes or dead letters; the Done marker and final snapshot are fixed protocol overhead, not added to that denominator. This is an amortized end-to-end instrument, not a pure instruction latency. Registered no-op snapshots do not exist: CoreStats counters remain maintained in both modes.

There is no observer-mode branch per callback/event. The snapshot choice is a template; pass timing and handler installation happen before start. The optional handler's increment is its actual measured work. Plain results and the captured reference live longer than the engine, are written by its sole worker, and are read after join. Named namespace `observability_bench` covers coroutine fixtures. The actor shapes and final-snapshot/FIFO contracts follow the existing `pass-timing.cpp` and `dead-letters.cpp` owners; the generic shared throughput sink cannot expose these owner-thread snapshots, so it is not duplicated or weakened.

Each cell first runs **both actual configurations** outside timing, then validates every measured batch after pausing. The oracle checks completion, checksum, core passes, exact received/dead-letter/reason/hook counts, no unexpected publication/drop/backpressure, timing **count** and engine error. It asserts no duration, percentile or threshold. Existing `qb-core-test-system-pass-timing`, `core-stats` and `dead-letters` retain ownership of the broader runtime contracts, including actual timing semantics and other dead-letter reasons. An invalid batch calls `SkipWithError`; the runner must reject its error JSON and retain the log. Use the existing external benchmark timeout; do not treat a hung negative control as valid work.

WARN output is filtered at CRIT once in this standalone executable (or logging is compiled out); stdout-only logging is refused because it cannot provide that filter. Dead-letter counters and rate-limit checks still occur with or without a hook. **Emitted logging cost is not covered.** The `enabled` descriptor refers to the selected pair's feature, not to all statistics. This instrument cannot prove the cost of always-maintained counters against a pre-feature runtime or an unsupported global “stats off” mode.

HTTP already provides lifecycle-hook 0/1/8 cells in four routing shapes (`qbm/http/tests/benchmark/routing/route-match.bench.cpp:435-438`). They are not rewritten or remeasured here. The current `dev/bench/cases.txt` route filter does not select those hook cells; their separate instrument roster still requires native calibration. `dev/bench/INSTRUMENTS.md` in the development superproject records coverage and exclusions. No generic future `on_<event>` family, unified module metrics API, or all-feature coverage is claimed. IO dispatch timing/offload/QUIC statistics and HTTP/module snapshots remain outside these six cells.


Build target `qb-core-bench-observability-overhead` through the normal benchmark configuration. Correctness smoke timings are discarded. The superproject supplies source-mutant controls and raw-counter validation; these tests do not certify a cost on another host.
